## Analyze: defects found while building

- "Admin" was first computed as "action `*` allowed" with partial matches as UNKNOWN; every
  principal with any permission then showed as a conditional admin. Root cause: an allow that
  covers only some actions cannot make anyone an admin, while a narrow deny can still remove
  admin. Fix: for the "every action" query, `Action`-list allows that are narrower than `*` are
  FALSE, while `NotAction` allows and narrow denies are UNKNOWN;
  covered by `test_any_action_is_admin_only_with_a_full_wildcard`.
- The venv's pip had two advisories; the check script and `make setup` now upgrade pip first.

## Security review fixes (2026-11-10)

An automated security review found two fail-open cases, both fixed with a test that fails
without the fix:

- A trust-policy Allow with `NotPrincipal` was skipped, so a role open to everyone except a few
  principals looked untrusted. It is now a wildcard grant (`*`) that lists the excluded principals.
  Account-root trust is also recognised in every partition (`arn:aws`, `arn:aws-cn`, `arn:aws-us-gov`).
- For the "every action" (admin) query, an Allow with `NotAction` (for example everything except
  `iam:*`) counted as not admin. It is now `conditional`, with the reason "NotAction allows every
  action except ...", so near-admins are visible.
