# Quality check against the 10 rules (2026-11-01)

Run on Windows 11 (Intel Core i7-13700H) with Python 3.14.5 in the repo's `.venv`, on 2026-11-09
(the file name matches the other repos). Mutations were applied one at a time by a script that
restores each file right after its pytest run (`-x`).

| # | Rule | Status | Evidence |
|---|---|---|---|
| 1 | Assume every call can fail | pass | The only external calls are boto3 `sts:AssumeRole` and the `GetAccountAuthorizationDetails` paginator: 5 s connect and 30 s read timeouts, botocore `standard` retries capped at 5 attempts, at most 500 pages (`collect.py`). AWS errors become `CollectError` with the cause chained (tested); nothing is swallowed. |
| 2 | Writes safe to retry | pass | The snapshot is parsed before it is written, then written to a temp file, fsynced and renamed (`write_atomic`); tests show a rerun replaces the whole file, a failed rename keeps the old file and no temp file is left, and an invalid collected document writes nothing. |
| 3 | No race conditions | N/A | Single-threaded CLI and library; no shared state. |
| 4 | Don't trust the clock | pass | Durations use `time.perf_counter` (monotonic); the stored `CollectedAt` is UTC with a `Z` suffix (tested). Dates in conditions are compared as aware UTC datetimes. |
| 5 | Read before changing | pass | No environment variables are read by the code; AWS credentials come from the standard boto3 chain, documented in the README. Every README link exists (audit). |
| 6 | Never break compatibility | pass | The snapshot format is AWS's own `GetAccountAuthorizationDetails` response, so output of the AWS CLI works unchanged; new fields go under `Metadata`. |
| 7 | One source of truth | pass | The read-only role policy lives once in `deploy/readonly-role/permissions-policy.json`; a test checks the lab account's role uses exactly it. Python >=3.11 in `pyproject.toml`, CI and README. |
| 8 | Small changes, no secrets, validate input | pass | Secret grep: only `EXAMPLE-NOT-A-SECRET` and `ASIAEXAMPLE` in fixtures and tests. Policies, snapshots, requests, role ARNs, external IDs and CLI arguments are validated with size limits; the wildcard matcher has no regex backtracking. |
| 9 | Tests that can actually fail | pass | Empty, invalid and failure paths covered (malformed policies and snapshots, API errors, page limit, failed rename). Randomized checks against a regex reference and policy invariants. 10/10 mutants killed. |
| 10 | Re-verify | pass | Results below; CI on push. |
